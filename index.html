Overview

What it does

User360 is a fraud- and risk-scoring platform for a large distributed field-agent network. Activity signals — device fingerprints, transaction timing, document-verification outcomes, and authentication logs — stream in continuously and are turned into one risk score and tier per agent, refreshed on a daily cadence with real-time alerting for the highest-confidence signals in between.

I designed and built the backend pipeline end to end: the feature-engineering layer, the statistical scoring framework, the orchestration and failure-recovery logic that keeps it running unattended, and the serving layer that feeds analyst dashboards and automated case escalation.

Domain and client details are generalized here to respect confidentiality. The architecture, engineering patterns, and my role below are representative of the system actually shipped.

Engineering

What made this hard

Decoupled scoring stages

Feature extraction, statistical normalization, and composite scoring are independent stages driven by a shared metadata registry — new behavioral signals or scoring formulas plug in without touching pipeline code.

Zero-downtime evolution

Ran two pipeline generations side by side under separate schedules so resilience features could be added and proven out without ever pausing the live scoring run.

Failure-aware retries

Hourly retry logic re-runs only the failed unit of work, guarded by idempotency checks so a retry can never silently double-count a score that already landed.

Real-time signal emission

High-confidence threshold crossings stream out to a message bus within minutes, independent of the daily batch cadence, feeding automated case escalation.

Cross-system consistency checks

An automated reconciliation job cross-checks the served copy of each score against its source of truth daily, catching silent drift before an analyst would.

Unattended-operation reporting

A daily health report — row counts, staleness, signal volume — is generated and distributed automatically, so pipeline health is visible without anyone watching logs.

My role

What I built

  • Designed the three-layer scoring architecture — from raw event streams to a single per-agent risk tier, with each stage independently schedulable and testable.
  • Built the orchestration and gating logic — promotion between stages, hourly retry-until-cutoff, and idempotency guards to keep reruns safe.
  • Implemented the statistical scoring library — rank, z-score, exponential decay, and Wilson-interval methods, dispatched by metadata rather than hardcoded per feature.
  • Wired up real-time alerting — threshold-based signal emission to a message bus feeding downstream case management.
  • Shipped the serving layer — the analytics store and consistency checks that keep dashboards and the operational registry trustworthy.
